## Overview
"Whatcha Got?" is a high-fidelity mobile prototype designed to reduce the everyday friction of deciding what to eat. It helps users discover and plan meals based on the ingredients they already have, their available time, mood, and budget.

## Problem
The question "what should I eat?" often leads to decision fatigue. Users with limited time, budget constraints, or specific ingredients at home struggle to find quick, relevant meal ideas without feeling overwhelmed by complex recipe apps.

## Target Users
* **Students:** Seeking affordable and quick meals.
* **People living alone:** Needing simple meal decisions for one.
* **Busy individuals:** Looking for time-efficient recipes.
* **Budget-conscious users:** Trying to keep meals within a strict budget.

## Core Features
* **Smart Filtering:** Filter recipes by available ingredients, time, mood, and budget.
* **Meal Discovery:** Personalized suggestions based on user goals.
* **Weekly Planner:** A visual calendar to organize meals for the week.
* **Recipe Details:** Step-by-step instructions with an intuitive, clutter-free interface.

## User Flow
The primary user journey focuses on quick decision-making:
`Onboarding → Login / OTP → Home (Discovery) → Search & Filtering → Recipe Detail → Weekly Meal Planner → Profile`

## How to Use
1. Open the [Figma Prototype](https://www.figma.com/proto/v2ik2R5nBVD2eoFSDrUJE7/High-Fidelity-Screens?node-id=0-1&t=YdO8ehHu6Zt3vr2H-1).
2. Navigate through the onboarding screens to understand the app's core value.
3. Use the search and filter functionalities to explore meal options based on ingredients or budget.
4. Click on any recipe to view details and add it to your weekly meal planner.

## Product / UX Architecture
The architecture is structured around four key inputs—ingredients, time, mood, and budget—ensuring that the primary discovery and planning flows remain focused and practical without overwhelming the user with unnecessary cognitive load.

## Design & UX Decisions
* **Decision Effort Reduction:** Replaced vague buttons (e.g., "Let's do this") with actionable, clear labels to eliminate user hesitation.
* **Component Consistency:** Built a reusable design system using Figma tokens (colors, typography, spacing) to ensure a consistent visual language across all screens.

## Edge Cases & Error Handling
Designing the happy path is not enough. The prototype accounts for:
* **Zero Search Results:** Encourages users to adjust ingredients/preferences.
* **Error States:** Clear toasts with "Retry" actions.
* **Offline State:** Communicates connectivity limits while allowing access to saved recipes.

## V2 Evaluation Results
Through usability testing, the initial design (V1) was iterated into the current version (V2). Task completion became seamless, and average task time was significantly reduced by optimizing the placement of primary actions and clarifying labels. *(Detailed metrics in the V2 Evaluation doc).*

## Limitations
This is a high-fidelity prototype demonstrating the UX/UI flow, not a production-ready application. Limitations include:
* Static recommendation logic (no real backend AI yet).
* Budget estimations are mockups and not synced with real-time grocery data.
* Offline functionality is simulated visually.

## AI-Assisted Workflow
AI was utilized as a thinking partner throughout the 8-week sprint for UX ideation, edge-case brainstorming, and usability analysis. It was used to structure thoughts and documentation, not to replace user validation or human design judgment.

## Future Improvements
Next steps for a production build would include integrating a real recommendation engine, larger recipe databases, ingredient image recognition, and real-time personalized grocery synchronization.
